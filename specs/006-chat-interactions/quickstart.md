# Quickstart: 会话消息交互改进

## 自动验证

从仓库根目录运行：

```powershell
npm run test
npx eslint .
npx tsc --noEmit
npm run build
scripts/verify.sh
scripts/check-lane.sh
```

无需新增依赖或配置。

## 手动验收

1. 打开一个任务会话，右键用户消息中的选中文本并加入待办；点击待办，确认目标会话内容就绪后立即滚动到对应用户气泡，整条气泡和命中片段约 1.4 秒后恢复。再检查无法匹配到用户消息的待办不会报错或误跳转，且仍保留。
2. 对一条未选中文字的用户消息打开右键菜单并加入收藏；在收藏列表中打开该收藏，确认回到同一会话和原消息，原消息未变化。
3. 在设置中配置 API 与至少两个 CLI；在空闲会话中逐一使用模型入口左侧选择器切换。打开 CLI 模型菜单，再点“切换 API/CLI…”，确认来源弹出项与左侧一致，且 CLI 默认、配置模型、候选列表和自定义模型选项仍可用；当前会话/新会话默认 Agent 同步、模型信息跟随、权限模式不变；助手消息头显示对应 Agent 名称，右侧上下文栏不重复显示。运行中确认来源切换不可用。
4. 展开含多个工具调用的助手回合，确认参数和结果内容仍在、冗余“参数/结果”标题已隐藏；检查状态、Diff、批准/拒绝按钮仍可用，长内容在固定高度区域内部滚动，外层回合仍可折叠。
5. 确认右侧“相关文件”合并消息提及、修改记录和已打开标签；相同路径仅出现一次。点击条目打开文件；按 Escape 关闭激活文件标签，未保存时取消关闭应保留文件与编辑内容。
6. 分别把新会话默认 Agent 设为 API 与 CLI，确认设置页对应配置标注“使用中”，且没有密钥内容。检查 API/CLI 空会话都显示“≈ 0”类的估算；增加或更新消息后估算更新，悬停/辅助提示明确其不是实际模型用量。
7. 展开项目待办卡片，确认头部不再显示固定和关闭按钮；点击标题仍可展开/收起，重新展开后待办内容保留。
8. 使用 `npm run web` 打开预览，确认浮动定位栏 `body > div.loc-bar` 不存在；按 Alt+Q 仍可启用/关闭 UI 定位，并确认悬停高亮、定位操作条和修改记录面板均可用。
9. 检查右侧上下文栏，确认用户指定的额外条目已移除；检查侧栏快速教程按钮位于设置按钮之后的最底部，点击后教程菜单仍可正常打开。
