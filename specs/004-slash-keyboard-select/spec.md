# Feature Specification: 斜杠命令菜单键盘选择

**Feature Branch**: `004-slash-keyboard-select`

**Created**: 2026-10-21

**Status**: Draft

**Input**: User description: "在会话输入框中输入 / 上下能选择输入"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 方向键选择并填入命令 (Priority: P1)

用户在会话输入框中输入 `/` 后，候选命令菜单弹出且第一条候选处于选中态；用户按 ↑ / ↓ 移动选中项，按确认键把选中的命令填入输入框（不发送），随后继续补全参数或直接发送，全程双手不离键盘。

**Why this priority**: 这是本功能的核心诉求。现状菜单纯展示：候选不能点选、方向键无响应，用户只能把命令全名打完，或者按 Enter 时把半截文本误发出去。键盘选择补齐后，斜杠命令才算真正可用。

**Independent Test**: 在任意会话输入框输入 `/`，仅用键盘（↓ 若干次 + 确认键）选中一条非第一位的命令，验证命令被正确填入输入框且未被发送。

**Acceptance Scenarios**:

1. **Given** 输入框为空，**When** 用户输入 `/`，**Then** 候选菜单出现且第一条候选呈现为选中态
2. **Given** 菜单已打开，**When** 用户按 ↓，**Then** 选中项移到下一条；按 ↑ 则移到上一条
3. **Given** 菜单已打开且某条候选被选中，**When** 用户按确认键，**Then** 该命令被填入输入框并进入「预置待执行」状态、菜单关闭、命令不执行，用户可继续补参数
4. **Given** 命令处于预置待执行状态，**When** 用户再次按 Enter，**Then** 命令才真正执行（发送/本地动作);在此之前用户修改或清空输入内容，预置即取消、内容按普通文本对待
5. **Given** 菜单未打开，**When** 用户按 Enter，**Then** 行为与现状一致（发送消息），不受本功能影响

---

### User Story 2 - 继续输入过滤与鼠标键盘一致 (Priority: P2)

用户输入 `/` 后继续打字时，候选列表按已输入内容实时变窄，选中项自动回到第一条匹配；鼠标悬停某条候选时选中态跟随移动，点击候选与键盘确认的效果完全一致；按 Esc 关闭菜单且输入内容保持不变。

**Why this priority**: 过滤与选择是连贯的一件事——列表变窄后若选中项还停在旧位置，确认填入的会是错误命令；鼠标用户与键盘用户若行为不一致，菜单会显得时灵时不灵。

**Independent Test**: 输入 `/s` 使列表变窄，验证选中项落在第一条匹配上；再用鼠标点击任意候选，验证填入结果与键盘确认一致。

**Acceptance Scenarios**:

1. **Given** 菜单已打开，**When** 用户继续输入字符使候选变窄，**Then** 选中项重置为第一条匹配候选
2. **Given** 菜单已打开，**When** 用户把输入删到只剩 `/`，**Then** 完整候选列表恢复，选中项回到第一条
3. **Given** 菜单已打开，**When** 用户鼠标悬停某条候选，**Then** 该条变为选中态；点击后该命令被填入输入框
4. **Given** 菜单已打开，**When** 用户按 Esc，**Then** 菜单关闭、输入框内容不变、焦点仍在输入框

---

### User Story 3 - 边界行为顺滑 (Priority: P3)

选中项位于列表首/尾时继续按 ↑ / ↓ 应循环到另一端；当过滤后无任何候选时菜单自动隐藏，方向键与 Enter 恢复普通输入行为（Enter 发送、多行文本正常换行浏览）。

**Why this priority**: 循环选择是命令菜单的通用惯例，能显著减少长列表里的按键次数；无候选时若按键仍被菜单逻辑拦截，用户会被困在发不出去的状态。

**Independent Test**: 在菜单中按 ↑ 选中最后一条、按 ↓ 回到第一条；输入一个不存在的命令前缀使列表为空，验证菜单消失且 Enter 能正常发送。

**Acceptance Scenarios**:

1. **Given** 选中项在第一条，**When** 用户按 ↑，**Then** 选中项跳到最后一条
2. **Given** 选中项在最后一条，**When** 用户按 ↓，**Then** 选中项跳回第一条
3. **Given** 已输入前缀无任何匹配候选，**When** 用户按 Enter，**Then** 按普通消息发送（或给出无匹配提示），不被菜单逻辑拦截
4. **Given** 菜单已打开，**When** 用户正在用中文输入法组字，**Then** 组字过程中的方向键/确认键不触发菜单选择

---

### Edge Cases

- 菜单打开时按 Enter 不得把未完成的 `/` 文本作为消息发送出去（误发送防护）
- 输入内容不再以 `/` 开头（删光或在行首插入其它字符）时菜单应立即关闭，方向键恢复文本编辑行为
- 候选只有一条时 ↑ / ↓ 不改变选中项，确认键正常填入该条
- 会话切换或输入框失焦时菜单不应残留在新会话上

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 候选菜单可见期间，菜单 MUST 始终呈现一个明确的当前选中项，且初始选中项为第一条候选
- **FR-002**: 菜单可见期间，用户 MUST 能用 ↓ / ↑ 在候选间移动选中项，且在列表首尾处 MUST 循环（首条按 ↑ 到末条、末条按 ↓ 到首条）
- **FR-003**: 菜单可见期间，确认键 MUST 把当前选中命令填入输入框并关闭菜单，且 MUST NOT 触发消息发送
- **FR-004**: 用户继续输入或删除字符使候选列表变化时，系统 MUST 实时按新内容过滤候选，并把选中项重置为第一条匹配
- **FR-005**: 菜单可见期间，Esc MUST 关闭菜单且不修改输入框内容；菜单关闭后方向键与确认键 MUST 恢复普通输入行为
- **FR-006**: 鼠标悬停候选 MUST 使该候选成为选中项，点击候选 MUST 与键盘确认产生相同结果（填入同一命令文本）
- **FR-007**: 无匹配候选时菜单 MUST 不可见，且任何按键 MUST 不被菜单逻辑拦截
- **FR-008**: 当前选中项 MUST 在视觉上与未选中候选明确可辨（与鼠标悬停态一致）
- **FR-009**: 确认选择后，命令 MUST 只被填入输入框并进入「预置待执行」状态，MUST NOT 在选择阶段直接执行（包括 /clear 等无参数命令）；用户再次按 Enter 才执行。预置状态 MUST 对用户明确可见；用户修改或清空输入内容后预置取消，该内容按普通文本处理（2026-10-21 负责人澄清，选项 C：两段式确认）

### Key Entities

- **斜杠命令**: 可被选择的命令条目，包含命令名、用法示例与一句话说明；集合沿用现有命令清单
- **候选菜单**: 输入 `/` 后出现的候选列表视图，包含当前过滤结果与当前选中项；选中项是其核心状态

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从输入 `/` 到把任意一条候选命令填入输入框，全程仅用键盘且按键次数不超过「目标位次 + 2」次
- **SC-002**: 菜单可见期间按确认键导致消息被误发送的次数为 0
- **SC-003**: 同一候选经鼠标点击与键盘确认两种方式填入的文本 100% 一致
- **SC-004**: 过滤条件变化后选中项落在第一条匹配候选的正确率为 100%

## Assumptions

- 菜单的触发规则沿用现状（输入内容以 `/` 开始时出现候选），本功能不改变触发条件与命令清单
- 确认键以 Enter 为主；是否同时支持 Tab 确认留待 plan 阶段决定（Tab 当前承担焦点移动，需避免破坏键盘可达性）
- 确认行为已澄清（FR-009）：两段式——选择只填入并预置，再按 Enter 才执行；不存在「选中即执行」的命令
- 目标场景为桌面键盘操作；触屏/移动端不在本期范围
- 中文输入法组字期间的按键不参与菜单交互（User Story 3 场景 4）
