# 威胁模型

> 架构变化时重新评审。对应 ADR 0002 与宪法 九–十四。最近评审：2026-10-20。

## 资产

- 用户的 API Key（可产生费用、泄露即被滥用）
- 用户项目中的源代码与项目外的个人文件
- 用户机器的执行环境（shell）
- 会话记录（可能含代码片段）

## 信任边界

1. **模型服务 → 主进程**：模型输出的文本与工具调用参数不可信。校验：工具参数按 `contracts/tools.ts` 的 JSON Schema 校验；路径经沙箱；副作用经权限决策 + 用户审批。
2. **渲染进程 → 主进程**：渲染进程显示不可信内容，视为可能被攻破。校验：preload 白名单通道；每个 IPC 参数运行时校验（`ipc/validate.ts`）；校验调用来源为 `app://bundle/`；渲染进程拿不到 Key。
3. **主进程 → 文件系统**：只允许项目根内（词法 + realpath）；会话 ID 正则限制，防止路径注入用户数据目录。
4. **主进程 → shell**：命令原文由用户逐条批准后作为单个参数交给 PowerShell / bash，工作目录为项目根。

## 威胁（STRIDE 速查）

| 类别 | 自查问题 |
|---|---|
| 伪装 | 攻击者能冒充用户或服务吗？ |
| 篡改 | 输入或存储数据能被悄悄改掉吗？ |
| 否认 | 出事后能查到是谁干的吗？ |
| 信息泄漏 | 敏感数据暴露给了谁？ |
| 拒绝服务 | 耗尽资源最便宜的方式是什么？ |
| 权限提升 | 低权限调用者能摸到管理操作吗？ |

## 本项目威胁

| 威胁 | STRIDE | 缓解措施 | 状态 |
|---|---|---|---|
| 提示注入让模型读取项目外文件（`../`、绝对路径、符号链接） | 信息泄漏 | `sandbox.ts` 词法 + realpath 双检查；单测覆盖 posix / win32 / 符号链接 | ✅ |
| 提示注入让模型静默改文件或执行命令 | 篡改 / 权限提升 | `permissions.decide` + 审批闸门；命令在任何模式都需批准；集成测试断言拒绝时无副作用 | ✅ |
| 模型输出中的 HTML/JS 在渲染进程执行（XSS → 调特权 IPC） | 权限提升 | Markdown 先整体转义；CSP `script-src 'self'`；沙箱渲染进程；XSS 单测 | ✅ |
| 渲染进程读取 API Key | 信息泄漏 | Key 只在主进程解密；`PublicSettings` 无 Key 字段；集成测试断言返回值与落盘文件均无明文 | ✅ |
| 服务端错误响应回显 Key 进入界面 | 信息泄漏 | `providerHttpError` 抹去 Key 再返回；测试覆盖 | ✅ |
| 页面导航到外部站点或打开新窗口 | 伪装 | 拦截 `will-navigate` 与 `setWindowOpenHandler`，外链交系统浏览器 | ❌ 无自动化测试（T040 跟踪，负责人 coordinator，到期 v0.2.0） |
| 会话 ID 构造路径写到用户数据目录外 | 篡改 | 会话 ID 正则 `^[A-Za-z0-9-]{1,64}$`；测试覆盖 | ✅ |
| 批准期间文件被用户修改，旧 diff 覆盖新内容 | 篡改 | 写入前比对原内容，不一致则放弃 | ✅ |
| 失控命令（死循环、长时间运行） | 拒绝服务 | 超时（默认 120 s，最长 600 s）+ 结束进程树 + 停止按钮 | ✅ |
| 模型无限调用工具 | 拒绝服务 | 每条用户消息最多 25 轮 | ✅ |
| 用户批准了有害命令（如删除文件） | 篡改 | 展示命令原文与 shell；责任在批准者 | ❌ 接受的风险（负责人：项目负责人，复审：v0.2.0） |
| 会话 JSON 明文存储代码片段 | 信息泄漏 | 存于当前用户的 `%APPDATA%`，受操作系统账户隔离；不含 Key | ❌ 接受的风险（负责人：项目负责人，复审：v0.2.0） |
| 开发依赖 `sprintf-js`（electron-builder → @electron/get → global-agent → roarr）moderate 级 DoS 告警，上游无修复版本 | 拒绝服务 | 仅打包期使用、不进入应用运行时；`.npmrc` `audit-level=high`；上游发布修复后升级 | ❌ 接受的风险（负责人：coordinator，到期：2027-01-31 复查） |
| 安装包未签名 | 伪装 | 无 | ❌ 接受的风险（MVP 不签名，负责人：项目负责人，发布前处理） |

> ✅ = 已缓解且有测试，❌ = 接受的风险（必须有负责人 + 到期时间）或已建任务。任何行都不许没有状态。
