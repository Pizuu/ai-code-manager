# 威胁模型

> 架构变化时重新评审。对应 ADR 0002 与宪法 九–十四。最近评审：2026-10-20。

## 资产

- 用户的 API Key（可产生费用、泄露即被滥用）
- 用户项目中的源代码与项目外的个人文件
- 用户机器的执行环境（shell）
- 会话记录（可能含代码片段）

## 信任边界

1. **模型服务 → 主进程**：模型输出的文本与工具调用参数不可信。校验：工具参数按 `contracts/tools.ts` 的 JSON Schema 校验；路径经沙箱；副作用经权限决策 + 用户审批。
2. **渲染进程 → 主进程**：渲染进程显示不可信内容，视为可能被攻破。校验：preload 白名单通道；每个 IPC 参数运行时校验（`ipc/validate.ts`）；校验调用来源为 `app://bundle/`；渲染进程拿不到 Key。
3. **主进程 → 文件系统**：只允许项目根内（词法 + realpath）；会话 ID 正则限制，防止路径注入用户数据目录。
4. **主进程 → shell**：命令原文由用户逐条批准后作为单个参数交给 PowerShell / bash，工作目录为项目根。

## 威胁（STRIDE 速查）

| 类别 | 自查问题 |
|---|---|
| 伪装 | 攻击者能冒充用户或服务吗？ |
| 篡改 | 输入或存储数据能被悄悄改掉吗？ |
| 否认 | 出事后能查到是谁干的吗？ |
| 信息泄漏 | 敏感数据暴露给了谁？ |
| 拒绝服务 | 耗尽资源最便宜的方式是什么？ |
| 权限提升 | 低权限调用者能摸到管理操作吗？ |
