# ADR 0007：简单 UI 修改跳过测试

- **状态**：已采纳
- **日期**：2026-10-20
- **决策人**：负责人（用户规则），coordinator 记录（宪法 1.2.0 原则 五）

## 背景

宪法 1.1.0 原则 五写的是「纯 UI 微调可跳过单测，但须在 PR 中注明」，但没有定义「纯 UI 微调」，实践中容易两头出错：要么为改一个间距去补 DOM 测试，要么把带逻辑的改动当成 UI 改动跳过测试。本项目渲染层是纯 DOM + CSS、无组件测试框架，视图层主要靠无头截图冒烟核对。负责人在功能 003 中给出规则：**简单 UI 修改跳过测试**。

## 决策

1. **定义**：简单 UI 修改 = 仅改 CSS、界面文案或 DOM 布局（元素结构、类名、位置），且不涉及 IPC / 契约、安全（路径沙箱、CSP、HTML 转义、密钥、审批）、数据逻辑（状态、解析、格式化、持久化）。
2. **要求**：此类改动不要求新增或修改测试；仍须 `npx eslint .`、`npx tsc --noEmit`、`npm run build` 通过；提交说明或任务卡注明「简单 UI 改动，按宪法 五跳过测试」。
3. **边界**：同一改动中触及上述逻辑的部分照常写测试（例如功能 003 中路径沙箱、右键内容组装、IPC 契约、配置为空处理写单测，视图 DOM 部分跳过）。
4. **落点**：宪法 1.1.0 → 1.2.0（原则 五），`AGENTS.md`「测试要求」同步一行。

## 考虑过的备选

1. 维持原文「纯 UI 微调可跳过单测」——没有定义，执行不一致。
2. 引入 DOM 测试框架（jsdom / Playwright 组件测试）覆盖所有视图——依赖与维护成本高，与 ADR 0001「不用 UI 框架、最少依赖」冲突；截图冒烟已能覆盖视觉回归的主要风险。

## 后果

- 好：纯视觉迭代更快；测试精力集中在逻辑与安全边界。
- 坏：视图层回归只能靠截图冒烟与人工核对发现。
- 接受的风险：判断「是否触及逻辑」依赖提交者自觉；审查时以「是否改了 IPC / 安全 / 数据逻辑」为准退回。
