# 测试策略

## 分层

- **单元**（`tests/unit/`）：纯逻辑、快、无 IO。每次变更都跑。
- **集成**（`tests/integration/`）：边界——数据库、API、文件系统。可用容器。
- **E2E**（`tests/e2e/`）：只覆盖关键用户旅程，保持小而精。

## 简单 UI 修改（宪法 五，ADR 0007）

- 仅改 CSS、界面文案或 DOM 布局，且不涉及 IPC / 契约、安全（沙箱、CSP、转义、密钥、审批）、数据逻辑（状态、解析、格式化、持久化）的改动：**不要求新增或修改测试**。
- 仍须 `npx eslint .`、`npx tsc --noEmit`、`npm run build` 通过；在提交说明或任务卡注明「简单 UI 改动，按宪法 五跳过测试」。
- 同一改动中触及上述逻辑的部分照常写测试；视觉回归用 `npm run web` + 无头截图核对。

## 执行

- 测试命令：`npm run test`
- 单元测试必须确定：无网络、无真实时间、无共享状态。
- 失败的测试阻塞合并。flaky 测试要隔离并修复，不许默默重试。
## 命名与覆盖

- 测试文件镜像源码结构：`src/<路径>/<名>.*` 对应 `tests/unit/<路径>/<名>.test.*`。
- 用行为命名测试：`rejects expired tokens`，而不是 `test1`。
- 纯逻辑追求高覆盖，胶水代码不刷数字；没人定期看的覆盖率就是装饰。
