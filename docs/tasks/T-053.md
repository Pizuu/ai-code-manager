## 目标

修「系统通知到的时候程序还没加载好」：主进程的事件发送是即发即弃（`src/backend/main.ts` 的 `emit` 只在窗口存在时 `webContents.send`，无暂存无就绪门），通知服务与 handlers 在窗口创建前就已注册。应用冷启动未就绪时产生的审批会立刻发系统通知，用户点击后 `notify-activate` 在渲染层还没订阅 / 数据还没加载完时被丢弃，前端 `jumpToApproval` 仅 rAF + 80ms 两拍重试，远盖不住冷启动——结果点击没反应、跳不过去。

## 允许修改的路径

特批双泳道，仅限：`src/backend/main.ts`、`src/backend/notify/*`、`tests/*/backend/*`、`src/frontend/main.ts`、`tests/*/frontend/*`。契约形状原则上不动；若就绪信号必须新增 IPC 通道，先报 coordinator 走契约（contracts 升版），不许私自加。

## 验收标准

- [ ] 渲染层未就绪时发生的通知点击（notify-activate）不丢失：就绪后被补发并完成跳转（以可注入的就绪信号 + 假时钟/假窗口单测证明暂存与补发各一次、不重复补发）
- [ ] 前端审批定位在数据异步加载未完成时能等到目标出现再定位（有上限的轮询，超时静默放弃不报错刷屏）
- [ ] 正常路径（已就绪时点击）行为不变；页面重载不导致旧激活被重复补发
- [ ] 相关单测 + `scripts/verify.sh` 全绿；check-lane 按双泳道特批口径自证文件面

## 不做什么

- 不改通知的分级、去重、升级与偏好门控口径（T-047 已定版）
- 不把全部 agent:event 都改成队列补发——只处理激活类关键事件，避免事件重放副作用

## 给 agent 的提示

就绪信号的选点先摸清前端 main.ts 的初始化顺序（store 首轮加载完成点）与既有 IPC 用法，能复用既有通道/事件就不要新开契约。主进程侧注意窗口重建（macOS activate 重开窗、页面 reload）时就绪标志的复位。
