## 目标

主进程长出通知服务：审批请求产生时按级别发系统通知（窗口不在前台才发系统通知这条口径由服务统一判断），以 approvalId 去重，P0 等待满 3 分钟升级一次；审批被解决后撤下对应通知状态；用户点击通知时聚焦窗口并按 v1.13 激活事件回传跳转目标。无系统通知能力的环境（Web 预览）通过能力标记明确降级，不假装已发。

## 允许修改的路径

严格等于 `.agents/lanes.conf` 中本泳道的 glob：`src/backend/* tests/*/backend/*`。

## 依赖契约

- contracts/ipc.ts v1.13（T-046）：激活事件、提醒偏好字段
- 既有审批事件流（agent:event）与会话状态（awaiting-approval / error）

## 验收标准

- [ ] 单元 + 集成测试：假通知器 + 假时钟下验证去重（同 id 只发一次）、3 分钟升级恰一次、解决后不再升级、偏好关掉的级别不发系统通知
- [ ] 点击通知的集成测试：窗口聚焦被调用且激活事件载荷正确（sessionId + approvalId）
- [ ] `scripts/verify.sh` 全绿
- [ ] `scripts/check-lane.sh backend` 全绿

## 不做什么

- 不做应用内弹窗与收件箱（T-048）。
- 不在系统通知上放批准 / 拒绝动作（spec FR-508 的安全边界）。

## 给 agent 的提示

Electron Notification 必须可注入替身，测试里不许真的弹窗。窗口前台判断与聚焦走既有 main.ts 窗口管理，别新开一套。升级计时在审批解决、会话删除时都要清干净，防悬挂定时器。
