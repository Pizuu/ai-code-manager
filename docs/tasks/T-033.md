## 目标

在接入 `opencode serve` 逐条审批之前，让 `ApprovalRequest` 能如实表达 opencode 除 edit / bash 外的权限类型：webfetch（URL）、doom_loop（重复工具调用）、task（子 agent）、external_directory（项目外目录）以及未知权限兜底（权限名 + patterns）。纯增量，不破坏既有使用方。

## 允许修改的路径

严格等于 `.agents/lanes.conf` 中本泳道的 glob：`contracts/* docs/SPEC.md docs/architecture/* specs/* .specify/memory/*`；另按派工说明登记本卡与 `docs/tasks/BOARD.md` 一行。

## 依赖契约

- contracts/ipc.ts v1.2 → v1.3

## 验收标准

- [x] `ApprovalKind` 新增 `webfetch` / `loop` / `subagent` / `external-dir` / `other`，`ApprovalRequest` 新增可选 `url`、`tool`、`permission`、`patterns`、`description`，中文 JSDoc 写明每种读哪些字段
- [x] 既有 `edit` / `command` 字段不变，backend / frontend 无需改动即可编译
- [x] `IPC_CONTRACT_REVISION` 升至 v1.3，登记 contracts/README.md 与 docs/SPEC.md 第 6 节
- [x] 样例：contracts/fixtures/agent-events.sample.json 新增 `ap-2`…`ap-6`（五种新种类各一）
- [x] spec 增量：specs/002-workspace-boards/tasks.md T126（done）、T127（backend）、T128（frontend）
- [x] `npx eslint .`、`npx tsc --noEmit`、`npm run test` 全绿

## 不做什么

- 不接入 serve 模式（T127，backend）；不改审批卡片渲染（T128，frontend）。
- 不改 `ApprovalDecision`（仍为批准 / 拒绝；serve 侧永不回复 `always`）。

## 给 agent 的提示

种类名按用户可理解的语义命名，原始 opencode 权限名放 `permission` 字段供审计；使用方遇到不认识的种类须回退为 `other` 展示，绝不默认批准。
