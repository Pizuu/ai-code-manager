## 目标

修复设置对话框 Agent CLI 页的「保存」按钮状态过期：按钮的 `disabled` 在打开对话框时按当时的设置快照一次性计算（`src/frontend/views/settings-dialog.ts` 约 :64–68），同一会话内经「自动检测 → 添加」新增第一条 CLI 后不刷新，按钮保持禁用（title「先添加一个 Agent CLI」），用户必须关窗重开或改用条目的「设为默认」才能继续。点击处理本身读的是最新 store 状态，只有按钮状态是旧的。

## 允许修改的路径

严格等于 `.agents/lanes.conf` 中本泳道的 glob：`src/frontend/* tests/*/frontend/*`。

## 验收标准

- [ ] 对话框打开期间 CLI 列表变化（新增第一条 / 删到空）时，「保存」按钮的 disabled 与 title 实时跟随：空列表禁用 + title 提示，非空可用 + 清 title
- [ ] 判定逻辑抽纯函数并有单元测试（本卡触及逻辑，不适用「简单 UI 修改跳过测试」）；对话框关闭后订阅必须解绑，不留悬挂监听
- [ ] `scripts/verify.sh` 全绿；`scripts/check-lane.sh frontend` 全绿

## 不做什么

- 不改保存的业务行为（目标 CLI 的选取口径、settings:set 载荷一概不动，只修状态刷新）
- 不动「设为默认」等条目级操作

## 给 agent 的提示

现成钩子：store 的 `settings` 主题订阅。注意本文件三个标签页（API / Agent CLI / 提醒）各自独立渲染，刷新逻辑只许落在 CLI 页的生命周期内，别把监听漏到对话框关闭之后。T-020 的 E2E（tests/e2e/frontend/boards-paths.test.ts）里有绕开此缺陷的注释与「设为默认」路径，修好后可把那段注释更新为正路（可选，不强制）。
